## Highest-impact findings

**P1** means a release-blocking correctness/integrity gap for the advertised feature. **P2** means a bounded behavior/maintainability repair. These priorities describe the affected feature, not a claim that every defect crashes every device.

| Priority / ID | Verified source evidence and impact | Smallest coherent repair and meaningful CI assertion |
|---|---|---|
| **P1 A01 — save success is not durable success** | `data/PresetStore.kt::save` discards `AtomicWrite.text == false`; `PresetRepository.save` returns `Unit`. `ui/VisualsHub.kt` clears the name/closes Save UI immediately. `VizStateStore.write` sets `dirty=false` before ignoring `SharedPreferences.commit()` result. `PaletteStore.save` likewise returns a palette after ignoring failure. Local `AtomicWrite` correctly preserves the previous file on failed replacement; the caller loses that outcome. | Propagate typed results, publish success only after commit, retain dirty/name state and offer retry. Add an injectable failing writer: failed update must preserve exact previous bytes and repository revision; UI must remain editable with an error and no success result. Successful retry produces one authoritative entry. |
| **P1 A02 — import allocation races with storage** | `PresetLibraryController.importPresetJson` derives a name from `host.vizState.value.presets`, optimistically appends, then launches `presets.save`. The list can still contain only built-ins, and separate operations can contend for the same storage identity. `refreshInitial` only merges the initial disk list if the current list is still the same built-in list instance. | Serialize name/ID allocation, durable write, and list publication in the repository. Do not allocate from UI state. Fixture: disk already contains `Shared`; import before initial refresh completes; both records survive, get distinct IDs, and appear once after recreation. Concurrent same-name imports also remain distinct. |
| **P1 A03 — Save copy can replace a look** | Files are keyed by display name. Main library Save uses `presetReplaceTarget` and confirmation, but the Customize “Save as preset” dialog calls `savePreset` directly. Repository has no separate copy/update commands or expected revision. A same-name save can overwrite independent of that main-screen check. | Introduce explicit `saveCopy` versus revision-checked `update`. A copy never overwrites, even from a different entry point or stale UI list. Test both Save entry points with an existing name; copy preserves old bytes, and explicit update requires the current ID/revision. Avoid a broad UI rewrite for this fix. |
| **P1 A04 — unbounded and weakly validated import** | `importPresetFile` uses `bufferedReader().readText()` without a byte limit. `PresetStore.fromJson` directly converts JSON doubles to floats and accepts scene IDs/enum-like integers without a complete validator or schema version. A finite Double such as `1e39` exceeds Float range. Link decoding is already bounded; that does not protect SAF files. | Read at most a documented limit plus one byte; parse off main; validate version, scene/assets, finite values, enum domains, bounded names/source lengths, and supported fields before modifying state. Test oversized/truncated streams, `1e39`, negative resource counts, unknown scene/version, and legacy defaults. Each rejected import must leave current look and repository untouched. |
| **P1 A05 — native parameter boundary accepts malformed numerics** | `NativeViz.setParams` packs raw fields; `geode_viz_set_params` checks only count; `SceneParams::set` directly assigns floats and rounds integer values without a finite/domain guard. `Renderer::setParams` accepts the whole struct. `VisualSafety::apply` constrains only a subset; it is not a full input validator. | Coordinate with native owner: validate the complete frame before committing it; reject before integer conversion, allocation, or GPU upload; retain last valid frame. Test native API NaN/infinity/extreme values, unknown names, wrong counts, and all enum boundaries. Kotlin admission validation and C++ boundary validation both remain necessary. Exact failing driver symptoms are runtime-pending. |
| **P1 A06 — saved/live/export look is incomplete** | `Preset` stores scene/scalars/attack/decay/custom GLSL/MilkDrop source, but omits modulation, layers, and fluid injection GLSL. `VizStateStore.write` explicitly writes null custom shader. `VisualSettingsController` communicates custom source by `MutableSharedFlow` with no replay. `applyPreset` sends source only when non-null, so selecting a built-in look does not explicitly clear an earlier custom program. | Persist one revisioned visual document with explicit built-in/custom shader mode and asset references; renderer reattachment consumes state, not a one-shot event. Test apply with no collector then attach; custom → built-in → restart; failed shader compile keeps last working program and editable draft. Named preset round-trip must retain supported modulation/layer/shader state. |
| **P1 A07 — export can differ from preview and change during analysis** | `VisualizerRenderer.exportSceneFactory` carries scene ID and current MilkDrop path only. `OffscreenRenderSpec` has no custom/injection source or layers. `OffscreenSceneRenderer.prepare` creates a new native renderer. `ExportController.startExport` reads parameters/modulators after asynchronous analysis; its animated `paramsAt` can read mutable `host.sceneParams` during rendering. | Freeze an immutable document revision before the job starts, resolve assets, and pass it to preview/offscreen evaluation. Test: start export, change live palette/scene/LFO while analysis is suspended, resume; export retains the original frozen configuration. A custom shader + layer fixture must reach the offscreen renderer. This is necessary state parity, not proof of identical live simulation history. |
| **P1 A08 — “take” is not full performance capture** | `PerformanceTake.State` contains only scene ID, scalars, and MilkDrop path. Recorder drops all events inside the 80 ms gap, including scene/path changes, and has no final pending-event flush. Null MilkDrop path is omitted, while replay only applies non-empty paths, so clears cannot survive. `ExportController.exportSceneIdFor` selects only `stateAt(0).sceneId`; the later `paramsAt` supplies scalars, not subsequent scene changes. No realized camera/touch/solver state is captured here. | First fix discrete event retention and explicit null clears. Separately implement actual live video/audio capture or a complete captured-performance timeline; do not describe scalar replay as recording the original generative performance. CI: A→B→C within 80 ms retains final C; clear a MilkDrop path then rewind/replay and it stays cleared; take A→B exports both scene intervals and transition. Native camera capture requires coordination. |
| **P1 A09 — broken/deceptive controls** | `CustomizeTabs` exposes Form drive; native search finds `formDrive` in serialization/interpolation tables only. Shader beat response is uploaded as zero; composite hit input is zero in `RendererFrame`. `ParamScope.of` defaults unknown keys to universal. | Remove inert controls from display, search, randomize, and modulation targets while retaining legacy fields for compatibility. Restore beat consumers only with the native owner's validated slice. CI capability test must fail unregistered render-control IDs; integration fixtures must show an effect for every advertised response control. A shader fix does not establish composite pulse/shake/flash support. |
| **P2 A10 — gesture pose changes a rate** | `TouchTransform.rotation` adds gesture degrees × `0.012` to `SceneParams.rotation`; native scenes integrate that value as radians/second. A twist therefore changes ongoing spin, not an absolute orientation. UV zoom and cyclic “Endless zoom” are not general spatial dolly/travel. | Separate pose, planar framing, and automatic rates; migrate old scalar semantics rather than silently changing saved looks. Test a twist/release: orientation holds unless explicit auto-spin is on. Test planar controls and actual spatial camera separately. Preserve every retained family. |
| **P2 A11 — ranges exceed effective output** | UI brightness/intensity maxima are 2, contrast 2.5, bloom/glitch 1; `VisualSafety` caps them at 1.25/1.25/1.25/0.25/0.25. Large upper slider regions cannot increase the effective value. Kotlin/native policy duplication also risks drift. | Keep safety limits; align advertised ranges or expose requested/effective values. Do not raise safety limits to make the slider move. Assert minimum/mid/maximum requested and effective values for each supported family, including reduced motion. Compare shared policy definitions through generated data or a contract fixture. |
| **P2 A12 — Reset and history are incomplete** | `ParamRandomizer.resetTab` infers ownership from randomization probes. `NEVER_ROLLED` includes visible quality/fade/master switches, so reset misses them. `ModulationController` history/A-B stores only scalars and groups edits by a 700 ms timing gap. `CustomizeSummary` compares with global defaults, not the loaded preset. | Declare section ownership independently of randomizability; use begin/end-edit transactions and document snapshots. Test Reset with fade and overlay switches changed; unrelated sections remain identical. Two separate quick edits undo separately; one drag with a pause undoes once. Loading a preset establishes a clean baseline. |
| **P2 A13 — device export support is guessed** | `ExportAspect.of` caps the long side at fixed 4096 and rounds only to even dimensions. `ExportCodec.hasEncoder` checks MIME presence, not dimensions/rate/bitrate/alignment. UI lists all qualities/codecs; retry changes codec/FPS/bitrate but never dimensions. `createEncoderByType` occurs before the attempt's `try`, so a creation exception bypasses the next candidate. | Query the chosen encoder's video capabilities and format support; negotiate a concrete supported plan and show any fallback. Keep explicit quality presets as user requests. Test fake capabilities with 16-pixel alignment, 1080-only/30 FPS, and no HEVC; reject/adjust before writing output. Inject encoder creation failure and verify fallback continues with released resources. Device verification remains required. |
| **P2 A14 — external mirror can destroy its previous copy** | `mirrorPresetToChosenFolder` deletes the existing SAF document before creating/writing a replacement and swallows errors. `materializeMilk` ignores a failed new-source write and can return an older file because it still exists. | Separate local-save and mirror status. Stage and verify provider output before retiring the last good copy where supported; report failed/pending backup. Return a typed MilkDrop materialization error instead of silently using stale source. Inject create/write/close failures; old mirror/local preset remain intact and applied source hash matches the chosen preset. |

## “Nothing hardcoded”: classify the value before changing it

The requirement should remove misplaced assumptions and disconnected settings, not erase mathematics, safety boundaries, or reproducible build configuration. No value becomes user-configurable simply because it is a literal.

| Class | Current examples | Correct ownership / action |
|---|---|---|
| **User configuration** | Palette, speed/spin, shader choice, background, modulation, transitions, camera goals | Stable typed parameter IDs and explicit defaults in a versioned visual document. Persist and restore; capability-aware UI; no hidden overwrite during rendering. English `ParamKeys` labels currently double as lock/randomization identities: split stable IDs from localized labels and migrate old keys. |
| **Device capability** | Codec support, alignment/resolution/FPS, GL target size, quality tier | Read actual platform/native capability; select a supported plan; keep runtime safety checks. Fixed `MAX_AVC_DIM=4096` is not a substitute. Do not label every target as 4K-capable from an enum. Coordinate GPU limits with native owner. |
| **Quality policy** | Export 720/1080/2160 presets and 6/12/40 Mbps defaults; full offscreen tier; shader/particle budgets | Named presets and a documented negotiation policy are legitimate. Their requested values must be reconciled with actual device limits. Offscreen rendering intentionally ignores wall-clock frame-rate pressure; it still cannot ignore real memory/codec/GL limits. |
| **Algorithm constants** | Time conversion, integration bounds, numerical epsilon, buffer limits, palette lookup resolution | Keep explicit, named, unit-bearing constants and explain invariants. Verify extreme inputs and sustained operation. A first-frame `1/60` fallback or bounded `dt` is not proof that the whole renderer ignores real time. |
| **Safety/resource policy** | Flash/luminance caps, reduced-motion scale, finite admission, import-size ceiling, event-count limit | Central policy shared/verified across boundaries; limits are not normal user bypasses. Import byte ceilings and event limits are useful. An 80 ms sampling policy must not discard a final/discrete event. Output safety still requires measured validation; a constant's name does not prove compliance. |
| **Schema/build/API identity** | JNI field names/order, preset version, dependency/NDK pins, MIME types, stable scene IDs | Keep stable and explicit. Pin versions for reproducible builds; migrate schemas deliberately. Preserve existing scene IDs so every C++ style and MilkDrop survives additions. |
| **Test/metadata fixtures** | `Random(0)` and probe seeds in `ParamRandomizer` metadata discovery | These are not evidence of a repeated live scene path. Replace fragile reflective ownership discovery with declared metadata for correctness, not merely to eliminate the seed. Fixed seeds remain appropriate in tests. |

## Bounded fix packages after the APK gate

1. **Storage outcome and safe copy/import (app/data owner):** A01–A04 and the app portion of A14. First introduce typed commit results, one writer, repository-owned identity allocation, bounded parsing, and separate copy/update. Preserve legacy data; do not combine a cosmetic UI rewrite or native render change. Repository tests with an injectable storage failure surface are the first useful gate.
2. **Parameter admission and honest capabilities (joint app/native):** A05, A09, A11. App owns import/typed metadata/UI; native owner validates C++ frames and restores approved consumers. Explicit cross-language contract tests cover names, types, enums, finite/range policy, and legacy defaults. Safety checks remain in the native boundary even after app validation.
3. **Complete visual document (app/native coordination):** A06–A07, then A12. Revisioned snapshot, explicit built-in/custom shader mode, modulation, layers, assets, renderer acknowledgement, lifecycle restore, frozen export input. A failed compile or write must not advance the saved/applied revision.
4. **Performance integrity (capture/export owner + native):** A08. Repair immediate timeline data loss, then satisfy the owner's actual-performance recording contract. Do not replace live generative motion with deterministic replay to make export easier.
5. **Device-aware export planning (export owner):** A13. Capability plan, truthful UI, safe retries, and decoded-output metadata assertions. Keep accepted user settings distinct from effective negotiated output.
6. **Gesture/camera migration (native camera owner + app controls):** A10. Preserve old styles, separate angle/rate, expose planar versus spatial capabilities, and bind new controls only after the C++ adapters exist. The separate visual-reference report supplies art direction and nine screenshot mappings.

## CI and review gates

- Add targeted tests with independent failure/input fixtures; do not write tests that merely restate implementation constants. Tests proposed here have **not** been run locally.
- Android unit/instrumentation: storage errors, bounded providers, cold restore, shader/built-in switching, copy/update entry points, fast discrete take events, null clears, export snapshot freeze, codec-plan negotiation.
- Native CI: reject malformed parameter frames transactionally; preserve the last valid state; prove supported consumer coverage and maintain existing scene IDs/MilkDrop. Native owner coordinates these files to avoid overlap.
- Emulator UI checks must inspect the UI hierarchy, tap actual node bounds, assert destinations/results, and preserve screenshots/logcat. A launched process or an APK artifact alone does not establish a working Save/import/export flow.
- Physical-device visual checks: preview/export document parity, actual captured touch/camera/scene transitions, no false 3D controls, sustained frame pacing/thermal/memory behavior. Hardware validation is still pending.
